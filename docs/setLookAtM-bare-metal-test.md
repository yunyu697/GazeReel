# setLookAtM 头锁定层 · 裸机测试指引

> 适用版本：alpha42 起（官方 Cardboard SDK 成为唯一底座之后）
> 目标：**不用电脑、不用 adb、不用摘手机**，在真机上判断「戴稳了？」那一层 UI 的左右眼是否对齐，并留下能直接定位到代码行的记录。

---

## 一、为什么单独测这一层

alpha42 之后工程里有**两条** UI 渲染路径，它们用的每眼矩阵不是同一套：

| | 头锁定层（本指引要测的） | 世界锁定层（片库 / 控制台 / 设置） |
|---|---|---|
| 出现时机 | 进 VR 后**未按触发键**时的「戴稳了？」 | 按触发键上膛之后的所有界面 |
| 每眼 view | `VrRenderer` 自研 `Matrix.setLookAtM(eyeX,0,0, …)`，只放一个 `±瞳距/2` 的眼位平移 | 官方 `LensDistortion.getEyeFromHeadMatrix(eye) × headView`，SDK 同时含眼位平移、镜片偏移与视场 |
| 投影 | 官方 `getEyeProjectionMatrix`（两边相同） | 同左 |
| 随头动 | **完全不动**（相机空间） | 跟着世界转 |

两条链**投影相同、view 不同**。所以「桶形畸变对不对」不在本指引范围；本指引只回答一个问题：

> 自研的那条 `setLookAtM` 眼位平移，和 SDK 的 `eyeFromHead` 在真机上差多少、差在哪个方向。

代码位置（交给开发时直接报文件名即可）：

- `app/src/main/java/com/gazereel/vr/render/VrRenderer.kt` → `uiMvpMatrix` 分支里的 `Matrix.setLookAtM(...)`
- `app/src/cardboard/java/com/gazereel/vr/render/CardboardHeadsetProvider.kt` → `eyeParams()` 里的 `getEyeFromHeadMatrix`
- 头锁定开关：`VrUiLayer.panelSpec()` 的 `headLocked = true`

## 二、裸机准备（一次，约 30 秒）

1. 手机端打开凝影 → 右上角**设置** → 把「界面大小」调到自己看得清的一档（默认 115%），**记下数值**。
2. 同一页确认「瞳距」是你实际的值。这一项**直接决定 `setLookAtM` 的 `eyeX`**，测试全程不要改。
3. 把手机放进纸盒、戴好，点「进入 VR」。
4. **不要按触发键。** 屏幕上会一直停在琥珀色边框的「戴稳了？」卡片 —— 这就是头锁定层，想看多久看多久。按了触发键就退出这一层；想重来只需退出 VR 再进一次。

> 不需要连电脑，不需要开 USB 调试，不需要装第二个 App。
> 也不需要额外的「自检开关」：**不按触发键本身就是常驻的头锁定层入口**。

## 三、五个观察动作

按顺序做，每条记住「正常」长什么样；有任何一条不符，直接跳到第四节判定表。

| # | 动作 | 正常应该看到 | 说明 |
|---|---|---|---|
| 1 | 双眼平视卡片，不转头 | 左右两幅「戴稳了？」卡片能合成**一个**，文字不重影 | 合成不了 = 两眼水平视差不对 |
| 2 | **只闭左眼**，再看 **只闭右眼** | 两眼看到的卡片水平位置差别很小，且卡片都还在各自画面中间 | 差别明显（一侧贴边、一侧居中）= `eyeX` 符号或量级不对 |
| 3 | 缓慢左右转头 ±20°，眼睛一直盯着卡片 | 卡片**一帧都不动**，不跟着头飘、不抖、不闪 | 会跟着动 = 误用了世界锁定的 mvp（历史的「闪」） |
| 4 | 缓慢抬头 / 低头 ±15° | 同上，卡片不动；上下边缘不被裁 | 只在这一层被裁 = 平面尺寸或 pitch 不对 |
| 5 | 按一次触发键 → 片库出现（切到 SDK 世界锁定层）→ 重复 1、2 | 片库也能合成为一个；若片库能合成而「戴稳了？」不能，问题**只在 `setLookAtM` 这一支** | 最关键的一组对照 |

第 5 步的意义：两条链共用同一副纸盒、同一个瞳距、同一个 SDK 投影，**只有 view 不同**。所以「哪一层合不上」就能把问题钉死在对应那一行，不用猜姿态、不用猜畸变、不用重测方向。

## 四、判定表

| 现象 | 最可能的原因 | 需要留给开发的证据 |
|---|---|---|
| 只有「戴稳了？」合不上，片库正常 | `setLookAtM` 的 `eyeX` 与 SDK `eyeFromHead` 的平移不等价（符号 / 量级 / 单位） | 第 1、2、5 步的闭眼描述 + 瞳距值 |
| 两层都合不上 | 瞳距设错、纸盒镜片距与设置差太多，**不是** `setLookAtM` 的问题 | 瞳距值 + 纸盒型号；先重调瞳距再测 |
| 卡片跟着头动 / 抖 / 闪 | `headLocked` 没生效，UI 走了世界锁定 mvp | 第 3 步描述 + 手机型号 |
| 卡片上下被裁、左右正常 | UI 平面尺寸与 SDK 投影视场不匹配（界面大小档位调高时更容易出现） | 界面大小档位 + 手机型号 |
| 两眼卡片亮度 / 大小明显不同 | 离屏 FBO 或 SDK 畸变合成，已超出本指引范围 | 截图 + 日志页内容 |

## 六、把结果交出来（仍在手机上完成）

1. 退出 VR → 配置页 → 右上角**日志**，把填好的内容连同页面一起截图。
2. 若出现过 native 崩溃，配置页会显示「上次进 VR 没成功」，点**详情**能读到 tombstone（alpha42 起支持），一并截图。
3. 日志页还有**界面快照**，用真实绘制代码渲染的 5 屏，可用来说明「字有多小 / 哪一格偏了」。

## 七、可选：连了电脑时

非必需，仅当开发要逐帧数值时才用：

```bash
adb logcat -b all -d | grep -Ei "gazereel|cardboard|headset|C5]" | tail -80
adb shell run-as com.gazereel.vr tail -80 files/run_log.txt
adb exec-out screencap -p > vr-screen.png
```

`run_log.txt` 里 `[headset] 官方 SDK 唯一底座` 与 `[C5] SDK 桶形畸变网格已装载` 两行都在，才说明底座完整跑起来了；缺任一行时先别下「视差不对」的结论。

---

**边界**：本指引只覆盖头锁定层的左右眼对齐。桶形畸变视场、视频上下翻转、头追方向、控制台自动淡出都不在这里判 —— 它们有各自的真机项，混在一起测会把结论带偏。
