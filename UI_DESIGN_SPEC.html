一句话结论。当前界面「粗糙」的主因不是配色，而是三处结构性错配：SetupActivity 锁定竖屏却使用横向双栏布局；VR 界面把 16–20 个凝视目标塞进一屏，最小目标仅约 2° 高；准星与字幕被画进同一张随面板俯角移动的 UI 纹理。本方案按「复杂前移 + 单屏 ≤ 9 目标 + 目标 ≥ 6°×4° + 屏幕空间独立层」四条硬约束重构，分 P0 / P1 / P2 三轮落地，不引入新依赖、不改动渲染管线主体。

2. 设计原则

01 复杂前移

所有文本输入、凭证、扫描、错误排查留在平面界面；戴镜后不出现键盘、不出现需要精确瞄准的小控件。

02 密度优先于总数

功能不删，靠分页与次级面板降低单屏密度。单屏 ≤ 9 个目标，主操作 ≤ 5 个。

03 角度而非像素

VR 尺寸一律以视场角度推导，再换算成 1024×512 纹理坐标，避免凭感觉定 px。

04 层分离

世界锁定 UI、屏幕空间准星、字幕各走独立绘制，互不牵连俯角与淡出。

05 状态可见

空 / 扫描中 / 成功 / 失败四态内联呈现，Toast 不再承载关键结论。

06 零依赖变更

保持 Theme.MaterialComponents.*，用现有库的 TextInputLayout + 自建 style 统一，不迁移 Material3。

技术决策：当前主题 parent 是 Theme.MaterialComponents.Light.NoActionBar。切 Material3 会改变所有 MaterialButton 默认外观并牵动 themes.xml、colors.xml 全局属性，收益与本次目标不匹配。TextInputLayout、MaterialAutoCompleteTextView、MaterialCardView 均已在现有 com.google.android.material 依赖中，直接可用。

3. 视场角推导与凝视目标基线

VrUiLayer.gazePoint() 中 halfWidth = atan2(0.9, 2.0) ≈ 24.2°、halfHeight = atan2(0.45, 2.0) ≈ 12.7°，故 2 米处的 1024×512 UI 平面对应约 48.4° × 25.4° 视场，即水平 1° ≈ 21.2px、垂直 1° ≈ 20.2px。Cardboard 下头部自然微颤约 ±1°，凝视目标需留出足够余量。

6.2 层分离

层当前位置目标位置理由
世界锁定 UIVrUiLayer 单张 1024×512 纹理不变，仅收至 10% 安全区并统一色板左右眼共用同一纹理，双眼融合一致
准星VrUiLayer.render():114-117 画在纹理中心拆为屏幕空间层：每眼视口中心各画一次固定 NDC 四边形，不参与头追矩阵与 panelCenterY准星必须对应真实视线中心；播放时面板下移 13° 不应带走准星
凝视进度环目标中心半径 30 的圆弧，同纹理保留在世界锁定 UI，但改为沿目标矩形外沿描边，半径与目标尺寸联动进度反馈属于目标本身，应贴合目标
字幕drawSubtitle() 同纹理，top=196独立屏幕空间层，固定在每眼视野中心下方约 6–8°，最多两行，行高 34px、字号 26px、宽度 ≤ 安全区 80%控制台淡出后字幕仍在，且不随面板俯角沉底

VrRenderer 当前在左右眼各绘制一次 UI 平面；拆层时复用同一次视口循环，在 UI 平面绘制之后追加正交投影的准星 / 字幕 quad 即可，不需要离屏 FBO，也不触碰 uBrightness、uEyeRegion 等已验证的着色器路径。桶形畸变仍是独立专项，本方案不涉及。

6.3 交互与动效

  • 凝视时长沿用 SettingsRepository 的 600–2400ms 可调值，默认不改；进度环 0→1 与此时长线性同步。
  • 控制台 8 秒无操作淡出现有逻辑（VrCoordinator.tick() + consoleTimeoutMs）保持不变，仅补淡入 120ms / 淡出 200ms 的透明度过渡。
  • 目标按下反馈 80ms 缩放至 0.97 + 描边高亮；触发键与凝视共用同一 targetAt() 判定，不新增输入分支。
  • 禁止视差、大幅位移与跟随头部的弹性动画，避免 VR 不适。
